# OneDrive Migration Configuration Guide

This guide helps you set up your application to use OneDrive and Microsoft Graph API instead of Google Drive.

## Prerequisites

You need the following to authenticate with OneDrive:
- Microsoft Azure Account
- Azure App Registration credentials
- OneDrive access for the authenticated user

## Step 1: Register Application in Azure

1. Go to [Azure Portal](https://portal.azure.com)
2. Navigate to **Azure Active Directory** > **App registrations** > **New registration**
3. Fill in the registration form:
   - **Name**: Your application name (e.g., "RAG Model Bot")
   - **Supported account types**: Select "Accounts in any organizational directory (Any Azure AD directory - Multitenant) and personal Microsoft accounts"
   - **Redirect URI**: Web - `http://localhost:3001/auth/callback` (adjust if your app runs on a different port)
4. Click **Register**

## Step 2: Get Client Credentials

1. In your app registration, go to **Certificates & secrets**
2. Click **+ New client secret**
3. Add a description and set expiration
4. Copy the **Value** (this is your `MICROSOFT_CLIENT_SECRET`)
5. Go to **Overview** and copy:
   - **Application (client) ID** → This is your `MICROSOFT_CLIENT_ID`
   - **Directory (tenant) ID** (if you need tenant-specific auth)

## Step 3: Configure API Permissions

1. In your app registration, go to **API permissions**
2. Click **+ Add a permission**
3. Select **Microsoft Graph**
4. Choose **Delegated permissions** (for user-based auth)
5. Search and select:
   - `Files.Read.All` - Read access to user's files
   - `Files.ReadWrite.All` - Read/write access to user's files
   - `offline_access` - Maintain access to user data offline
6. Click **Add permissions**
7. Click **Grant admin consent for [Your Organization]** if applicable

## Step 4: Update Environment Variables

Create or update your `.env` file with the following:

```env
# Microsoft Graph API Configuration
MICROSOFT_CLIENT_ID=your_client_id_here
MICROSOFT_CLIENT_SECRET=your_client_secret_here
MICROSOFT_REDIRECT_URI=http://localhost:3001/auth/callback

# OneDrive Configuration (optional - for specific folder)
ONEDRIVE_FOLDER_ID=your_folder_id_here

# Slack Configuration (existing)
SLACK_BOT_TOKEN=your_slack_bot_token
SLACK_APP_TOKEN=xapp-xxxx

# Other existing configs...
```

## Step 5: User Authentication Flow

### For Initial Authentication

1. When a user first uses the bot, they need to authenticate:
   - Call the authentication URL generated by the bot
   - The user is redirected to Microsoft login
   - After login, they're redirected back with authorization code
   - The bot exchanges the code for access and refresh tokens
   - Tokens are stored securely in `microsoft_api/tokens.json`

### In Slack Commands

The bot now automatically:
1. Checks if user's token is still valid
2. Refreshes token if expired
3. Uses the access token to query OneDrive via Microsoft Graph API

## Token Management

### Token Storage

Tokens are stored in `microsoft_api/tokens.json`:
```json
{
  "user_slack_id": {
    "access_token": "...",
    "refresh_token": "...",
    "expires_in": 3600,
    "token_type": "Bearer",
    "scope": "...",
    "expiresAt": "2026-04-19T...",
    "savedAt": "2026-04-19T..."
  }
}
```

### Token Refresh

Tokens are automatically refreshed when:
1. A command is executed and token is found to be expired
2. The `tokenManager.getValidAccessToken(userId)` function is called
3. Manual refresh via `tokenManager.refreshTokens(userId)`

## Troubleshooting

### "User not authenticated" Error
- User needs to complete OAuth flow first
- Share the authentication URL with the user
- Ensure redirect URI matches your deployment URL

### "HTTP 401 Unauthorized" Error
- Access token may have expired
- Token refresh might be failing
- Check `MICROSOFT_CLIENT_SECRET` is correct

### "HTTP 403 Forbidden" Error
- App doesn't have required permissions
- Check API permissions in Azure app registration
- May need admin consent

### OneDrive Files Not Loading
- Ensure user has OneDrive access
- Check file access permissions
- Verify user_id is stored in tokens.json
